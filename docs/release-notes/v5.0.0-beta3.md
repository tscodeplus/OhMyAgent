v5.0.0-beta3：内置 pi-mono 升级到 v1.5.0（工具参数校验换成不起 eval 的 `pi-schema`），并修掉一批设置、收件箱与笔记页的问题。

## ⬆️ pi-mono v1.5.0

- 项目内置的 pi-mono 升级为 pi v1.5.0（308 个上游提交）
- 工具参数校验从 TypeBox 换成新的 `pi-schema`：不依赖 `eval` 的 JSON Schema 校验器（draft 2020-12 / 7，编译成闭包），校验失败会指出具体字段路径
- `AgentTool` 的参数泛型放宽为 `object`，我们 61 处 TypeBox 工具定义无需改动，行为不变
- anthropic / bedrock / openai / mistral / google 的 API 适配与流式 JSON 解析同步上游
- 5 个本地补丁文件、27 处 `OhMyAgent` 标记全部干净合并

## 📝 笔记

- 笔记库改为带页码的分页（每页 20 条）：批准、置顶、归档之后停在当前页，不再被弹回第一行
- 驳回的草稿现在直接删除，不再归档——以前驳回后点一次「恢复」就会把你不想要的笔记发布出去
- 「已归档」是入口而不是徽标：计数为 0 时不再消失，清空待审或归档队列后会回到对应的列表
- 计数用紧凑格式显示（`1万` / `10K`），不再把「新建笔记」挤出窄栏

## ⚙️ 设置

- 内置 provider 重命名不再打一个字符就失焦；设置里保存的自定义模型立刻出现在所有模型下拉中（以前要重启进程）
- judge 设置：新增条目后自动展开并滚动到可见位置；行头 X 改为垃圾桶图标；删除 provider 组或自定义 judge 需要确认；自定义中转 judge 的 Key 现在和 API key 一样打码
- 新会话的默认标题跟随界面语言（中文界面是「新对话」）

## 🔧 修复

- 删除 IM 会话后不再留下一条空白的「新会话 / 0 条消息」，收件箱徽标也不会再凭空计数（`sessions.is_placeholder`，migration v38）
- 收件箱里原先标着「收件箱」的分区改为「渠道会话 / Channels」，与内容一致
- 技能激活时回复不再消失：回答正文会作为文本段落一起持久化，不再只剩「技能激活」卡片
- 桌面端窗口的关闭按钮悬停变红

v5.0.0-beta3 upgrades the embedded pi-mono to v1.5.0 (tool-argument validation moves to `pi-schema`, which needs no `eval`) and fixes a batch of settings, inbox and notes-page problems.

## ⬆️ pi-mono v1.5.0

- The embedded pi-mono is upgraded to pi v1.5.0 (308 upstream commits)
- Tool-argument validation moves from TypeBox to the new `pi-schema`: an `eval`-free JSON Schema validator (draft 2020-12 / 7, compiled to closures) that names the exact field path when validation fails
- `AgentTool`'s parameter generic widens to `object`; our 61 TypeBox tool definitions need no change, and behaviour is unchanged
- anthropic / bedrock / openai / mistral / google API adaptations and streaming-JSON parsing follow upstream
- All 5 locally patched files and all 27 `OhMyAgent` markers merged cleanly

## 📝 Notes

- The library pages with numbered pages (20 rows each): approving, pinning or archiving keeps you on the page you were reading instead of dropping you at the first row
- Rejecting a draft now deletes it instead of archiving it — one click on 恢复 used to publish an unreviewed note you had explicitly refused
- 已归档 is a destination, not a badge: it no longer disappears at a count of 0, and emptying the review or archive queue returns you to the list the note now lives in
- Counts use a compact format (`1万` / `10K`), so a large number no longer pushes 新建笔记 out of a narrow column

## ⚙️ Settings

- Renaming a built-in provider no longer loses focus after one character, and a custom model saved in Settings appears in every model picker immediately (it used to need a process restart)
- Judge settings: a new entry expands and scrolls into view; the row header's X is now a trash icon; deleting a provider group or a custom judge asks for confirmation; a custom relay judge's key is masked like the provider API keys
- A new session's default title follows the UI language

## 🔧 Fixes

- Deleting an IM transcript no longer leaves an empty 新会话 / 0 条消息 row behind, and the inbox badge stops counting rows nobody created (`sessions.is_placeholder`, migration v38)
- The inbox section labelled 收件箱 is now 渠道会话 / Channels, which is what it holds
- A reply no longer disappears when a skill is activated: the answer body is persisted alongside the skill card instead of being lost with it
- The desktop window's close button turns red on hover
