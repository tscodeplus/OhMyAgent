v5.0.1 修复消息全文索引的长期漂移，修掉远程网关把可用令牌报成「令牌无效」的误判，以及错误令牌导致桌面端再也打不开的问题。

## 🔎 检索索引

- **修复：WebUI 里的审批卡、问答卡与 `/` 命令写入的消息搜不到。** 这些写入走了裸 SQL、跳过中文全文索引同步，现在统一经 MessageRepository（新增 `upsert()` 保留原有 replace 语义）；正文为空的卡片不再建索引
- **修复：删除项目后消息索引留下孤儿行。** 删项目时一并清理对应 FTS 行，此前裸 DELETE 会留下指向已不存在消息的索引
- **新增：每次启动做一次索引自检。** 正常情况下只跑两次 COUNT，索引与消息对不上时在事务内重建——v10 迁移只回填过空索引，部分回填或被绕过的写入此前没有任何机制能自愈
- **修复：回填之后写入的消息丢了时间戳。** 数值绑定写进 TEXT 列会落成 `1793618776783.0`，`parseEpochMs` 把这个形式解析成 0，现在接受它
- Termux 部署脚本的索引校验改为 anti-join：旧写法要求「索引行数等于消息总数」，凡是展示过审批卡的设备都会误报，而真正缺失的消息只体现为一个数字

## 🖥️ 远程网关连接

- **修复：桌面端「测试连接」把可用的令牌报成「网关在线但令牌无效」。** 页面上跨域 GET 携带 Authorization 会先发 OPTIONS 预检，鉴权钩子跑在 CORS 之前、直接用 401 挑战它，浏览器于是丢弃真实请求；同一个令牌用 curl 打 `/api/auth/verify` 是通过的（`/api/health` 公开，所以版本号还拿得到）
- 鉴权放行 OPTIONS 预检（规范上预检不带凭据、也不读数据），POST/PUT/DELETE/PATCH 仍然返回 401
- 桌面端改由 Node 侧探测（`/_desktop/gateway-test`）：没有 Origin、没有预检，面对尚未升级的网关也能给出关于令牌本身的结论；探测抛错时显示「无法连接」而不是「令牌无效」

## 🐞 桌面端启动

- **修复：`desktop-config.json` 里存了错误令牌后应用再也打不开。** 关掉 splash 时它是唯一窗口，wry 把窗口表清空视为退出请求，进程在排队中的选择器窗口注册之前就退了，只剩一个随进程消失的托盘图标
- 选择器与 splash 现在在同一主线程任务里按「先建后关」处理；控制端口未知或建窗失败时回落到错误弹窗，不再留下没有窗口的进程
- 启动超时、sidecar 崩溃、重启失败三条路径原本也是先关后建，一并改正

v5.0.1 fixes long-running message full-text index drift, a remote-gateway verdict that called a working token invalid, and a wrong token that left the desktop app unopenable.

## 🔎 Search Index

- **Fixed: messages written by WebUI approval cards, question cards and `/` commands were unsearchable.** Those writes used raw SQL and skipped the Chinese full-text index sync; they now go through MessageRepository (new `upsert()` keeping the replace semantics), and cards with an empty body are no longer indexed
- **Fixed: deleting a project left orphan rows in the message index.** The FTS rows are pruned with the project; the raw DELETE used to leave index entries pointing at messages that no longer exist
- **New: an index self-check on every boot.** Two COUNTs normally, and a transactional rebuild when the index and the messages disagree — migration v10 only backfills an empty index, so nothing ever healed a partial backfill or a bypassed write
- **Fixed: messages indexed after the backfill lost their timestamp.** A numeric bind renders into a TEXT column as `1793618776783.0`, which `parseEpochMs` read as 0; that form is accepted now
- The Termux deploy script now verifies the index by anti-join instead of `indexed == total`, which misfired on every device that had ever shown an approval card while a genuinely missing message only ever looked like a number

## 🖥️ Remote Gateway Connection

- **Fixed: the desktop "Test Connection" reported a working token as "gateway online but token invalid".** A cross-origin GET carrying Authorization needs an OPTIONS preflight, and the auth hook ran before CORS and challenged it with 401, so the browser dropped the real request; the same token passes `/api/auth/verify` with curl (`/api/health` is public, which is why the version still came back)
- Auth now lets the OPTIONS preflight through (by spec it carries no credentials and reads nothing); POST/PUT/DELETE/PATCH still get 401
- The desktop probes remote gateways from Node instead (`/_desktop/gateway-test`): no Origin, no preflight, so the verdict is about the token even against a gateway that has not been upgraded; a thrown probe now reads "unreachable" instead of "invalid token"

## 🐞 Desktop Startup

- **Fixed: a wrong token in `desktop-config.json` made the app unopenable.** Closing the splash while it was the only window emptied wry's window map, which tauri-runtime-wry turns into an exit request, so the process quit before the queued chooser window was registered — leaving only a tray icon that died with the process
- The chooser and the splash are now built and torn down in one main-thread task, chooser first; an unknown control-API port or a failed window falls back to the error dialog instead of leaving the shell windowless
- The startup-timeout, crashed-sidecar and respawn-failure paths had the same close-then-show order and are fixed the same way
