## 🧩 判断内核

- **自动晋级改为真正的统计门槛**：一致率取 Wilson 单侧 95% 下界，并要求可比较样本数达标——此前十个可比较样本就能越过 90%/95% 的门槛，无论身边堆了多少灰区记录
- **服务层兜底不再只抬高总数**：无 key、熔断打开、被中止、引用不支持、模型未知等失败单独计入，不再稀释一致率
- **统计窗口收敛到最近 90 天、且只算当前链能产出的决策点**，换供应商或换模型后旧历史随之退休；环境性故障的兜底行予以保留
- **影子决策与兜底从未分歧的决策点不允许晋级**：30 次以上比对 100% 一致说明晋级只是每轮多花一次裁判调用、结果不变
- **设置面板给出可解释的判决**：门槛判决带结构化原因并本地化（中英），同屏展示逐点阻塞项、灰区 key 明细与最近一次应用记录
- 按 key 统计灰区命中，灰度兜底在判决与记录中保留 `grayAnswers` / `grayKeys`
- 两个最容易骑墙的决策点补上状态：`tool.risk` 携带本会话最近几轮用户发言，`context.forget` 候选携带用户之后转去聊了什么；两者规格升到 v2，清理会话时同步丢弃逐轮上下文

## 🌙 夜间记忆维护

- **修复：积压超过一批时尾部可能永远轮不到，中断后也从别处重新开始。** 合成阶段改用行游标（migration v39）按 rowid 顺序推进，游标持久化在维护记录上；不能按 `created_at` 排序，因为该列是 TEXT、混装着 epoch 数字与 ISO 字符串
- **修复：阶段超时形同虚设，一个卡住的阶段会让整轮永远挂起，而重排下一次的调用写在那一轮的 finally 里，夜间维护就再也不会启动。** 超时现在用 `Promise.race` 强制生效，被放弃阶段的迟到异常只记日志
- 阶段顺序改为 embed → purge → hygiene → synthesize → sceneCluster，长耗时的整合阶段无法再饿死召回所依赖的向量回填
- 场景文档新增字节上限 `memory.sceneClustering.maxFileBytes`（默认 256KB，0 为不限），超出从尾部截断并留计数标记，不再随对话无限增长
- **修复：场景聚类从第二轮起把 `scenes.bak` 整份留在磁盘上。** 成功跑完即删除
- **修复：合并后的记忆只同步了全文索引，去重与向量召回仍按合并前的文本打分。** 合并后重新做 embedding 与提词
- **修复：在没有向量通道的降级检索里，中文恰好退到旧分词器。** 该通道现在与混合通道一样优先走 jieba 全文索引
- 偏好冲突解析改用统一的 `parseEpochMs` 解析时间戳，不再自带一套

## 🎬 场景聚类

- 按 scopeKey 游标分批推进（`memory.dreamCycle.sceneClusterBatchSize`，默认 8，0 为不限），每个 scopeKey 独立提交——文件原子写入、行独立 upsert，进度因此可以被表达和续跑
- 单点失败不再连累已成功的 scopeKey：整目录快照回滚被移除（部分成功时「全部回滚」丢掉的正是成功的那部分），上一版本遗留的 `scenes.bak` 会在下次运行时清理
- 已提交的 scopeKey 参与对账：本次不再产出的文件与 `scene-*` 行会被删除，匹配按精确命名形状进行，避免把 `chat_A_2` 当成 `chat_A` 的文件清掉
- 无活跃行引用的孤儿文件随后清扫，覆盖路径净化带来的丢失与登记失败的行
- 队列改为「有记忆的 scopeKey ∪ 只剩场景行的 scopeKey」，记忆被全部删除的 scopeKey 也会被对账，不再对所有运行都不可见
- 删除两个零调用的死模块（`memory-pipeline.ts`、`fallback-retriever.ts`），其中 L0–L3 计数与实际渲染该状态的 SQL 早已不一致

## ⬆️ pi-mono Upgraded to v1.6.0

- New models GPT-6.2 Astra/Sol, qwen4-max-preview and deepseek-v4.1-flash, with regenerated provider data
- Wider retry coverage: bare socket codes, `connection reset by peer`, `Connection closed.`, and the Codex WebSocket lifetime — dropped streams recover more often
- An aborted signal now yields an `Operation aborted` tool result before tool lookup and hooks
- `openai-completions` sends the developer role only to api.openai.com; Anthropic message threads widen to any baseUrl on api.anthropic.com
- App dependencies raised to openai 7.59.0 and @google/genai 2.32.0

## 🧩 Judge Kernel

- **Autopilot promotion now needs real statistical evidence**: agreement is gated as a Wilson one-sided 95% lower bound, with a floor on comparable samples — ten comparables used to clear a 90%/95% bar no matter how many gray entries surrounded them
- **Service-layer fallbacks no longer just inflate the total**: no-key, circuit-open, aborted, unsupported-ref and unknown-model failures are counted on their own instead of diluting agreement
- **Statistics are windowed to the last 90 days and to the points the current chain can produce**, so a provider or model swap retires the old history; fallback lines for environmental outages are kept
- **A point whose shadow decisions never diverged from the floor cannot promote**: 100% agreement over 30+ comparisons means promotion would change nothing while paying a judge call every turn
- **The settings panel explains the verdict**: structured, localized gate reasons (zh-CN + en) alongside per-point blockers, gray-key detail and the last applied record
- Gray hits are counted per key, and gray fallbacks keep `grayAnswers` / `grayKeys` on the verdict and in the ledger
- The two points that hedged most gain state: `tool.risk` carries the session's recent user turns and `context.forget` candidates carry what the user moved on to; both specs move to v2, and clearing a transcript drops the per-turn context

## 🌙 Nightly Memory Maintenance

- **Fixed: a backlog larger than one batch could leave the tail unvisited forever, and an interrupted run restarted somewhere else.** Synthesize now walks memories by rowid behind a cursor persisted on the maintenance record (migration v39); `created_at` is unusable for ordering because that column is TEXT mixing epoch digits and ISO strings
- **Fixed: phase timeouts were advisory, so one hung phase left the run pending forever — and the re-arm lived in that run's finally, so the nightly cycle never started again.** Timeouts are enforced with `Promise.race`, and the abandoned phase's late rejection is logged
- Phase order is now embed → purge → hygiene → synthesize → sceneCluster, so a long consolidation cannot starve the vector backfill recall depends on
- Scene documents gain a byte ceiling (`memory.sceneClustering.maxFileBytes`, default 256KB, 0 = unlimited), truncating from the tail with a clipped-count marker instead of growing with the conversation
- **Fixed: from the second run onwards scene clustering left a full `scenes.bak` duplicate on disk.** A successful run drops it
- **Fixed: merged memories only had their full-text index updated, so dedup and vector recall scored them against their pre-merge text.** Merging now re-embeds and re-terms the row
- **Fixed: with no vector lane, the degraded retrieval path dropped to legacy tokenization exactly where Chinese recall had nothing to compensate.** It now prefers the jieba index like the hybrid lane
- Preference conflict resolution uses the shared `parseEpochMs` instead of its own timestamp parsing

## 🎬 Scene Clustering

- ScopeKeys are processed in batches behind a cursor (`memory.dreamCycle.sceneClusterBatchSize`, default 8, 0 = uncapped) and committed independently — atomic file write, per-row upsert — so progress can be expressed and resumed
- One failing scopeKey no longer takes down the ones that already succeeded: the whole-directory snapshot rollback is gone (under partial success it discarded exactly the work that succeeded), and a `scenes.bak` left by the previous implementation is removed on the next run
- Committed scopeKeys are reconciled: files and `scene-*` rows the run no longer produces are deleted, matched by exact name shape so `chat_A_2`'s files are not pruned as `chat_A`'s
- Orphan files no active row references are swept afterwards, covering lossy path sanitisation and rows whose registration failed
- The queue is now "scopeKeys with memories ∪ scopeKeys with only scene rows", so a scopeKey whose memories were all deleted is reconciled instead of being invisible to every run
- Two dead modules with zero production callers are deleted (`memory-pipeline.ts`, `fallback-retriever.ts`); the pipeline's L0–L3 counts had long disagreed with the SQL that renders that status
