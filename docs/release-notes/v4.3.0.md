## 🧩 新增：判断内核（主要更新）

- 在 15 个关键环节引入"裁判"判定：意图分类、技能披露、记忆捕获 / 价值 / 合并、上下文遗忘与压缩、偏航检测、收尾验证、风险命令复核、注入筛查、群聊分诊、通知路由、工具输出准入等；每个决策点可设为 关闭 / 影子（只记录不生效）/ 生效，默认全部影子，行为与引入前完全一致
- 裁判链在 WebUI 中拖拽排序：内置分类器供应商（OpenCode、Typesafe、Vercel AI Gateway、OpenRouter、Cloudflare Workers AI 免费档）与自定义中继裁判平级混排，第一个可用者为主裁判，主裁判灰区或失败时依次顺延，全部不可用时回落到原有规则；风险命令复核只能收紧（至多要求审批），绝不放行
- 自动晋升：影子点攒够样本后按统计闸门（样本 ≥30、一致率 ≥90%、灰区率 <20%）自动转生效，质量退化自动退回，无需人工标注；也可在 config.yaml 手动固定某个点
- WebUI 新增「判断内核」标签页（启停、供应商与模型、裁判链、金样例测试、决策点矩阵）与判决台账面板；配置以 `config.yaml` 的 `judge:` 节为唯一来源
- 隐私默认安全：账本默认不保存被审内容，密钥只允许以环境变量名引用；连续失败进入熔断并静默兜底

## ⬆️ 升级 pi-mono 至 v1.3.0

- 项目内置的 pi-mono 升级为 pi v1.3.0
- 模型与供应商更新：Codex GPT-6.1 Sol 支持 500K 上下文；Claude Haiku 5.5 / Opus 5 可关闭思考；Xiaomi MiMo 增加思考开关；kimi-coding 回到 Chat Completions
- 上游修复一并采纳：`The upstream provider returned an error`、`The service is temporarily unavailable` 等错误改为可重试；Anthropic 严格工具上限失败时回落；Claude 的工具错误结果保留图片；非 Claude 模型不再丢弃思考内容；工具参数残缺时报错而非截断
- MCP：工具返回的 `structuredContent` 接受任意 JSON 值；被取消的请求在授权刷新后不再重试

## 🔧 修复

- **修复：新会话的首条消息在历史里重复出现两遍。** 首轮之前插入的工具声明系统消息让落库窗口错位一格，同一条用户消息被写入两次
- **修复：配置热重载可能被上一次的旧配置覆盖。** 多个重载（文件监听、WebUI 保存、环境变量）并发到达时按到达顺序串行应用
- **修复：微信渠道消息可能重复处理或丢失。** 批次先处理成功再提交游标，失败批次按指数退避重试且已完成的消息不重跑；回复令牌改为顺序写入
- **修复：飞书渠道队列满时消息被静默丢弃。** 队列拒绝现在会被上报，单条任务失败也不再阻塞同会话的后续消息
- **修复：长时间运行后会话的 agent / 模型 / 思考档位映射无限增长。** 三张映射表改为有界（上限 500，淘汰最久未用）

v4.3.0 is the stable release: it introduces the Jev Judge Kernel, upgrades the embedded pi-mono to v1.3.0, and fixes channel delivery, config hot-reload and message persistence.

## 🧩 New: Judge Kernel (Main Update)

- A "judge" now decides 15 key steps: intent classification, skill disclosure, memory capture / worth / merge, context forgetting and compaction, turn drift, turn completion, risky-command review, injection screening, group-chat triage, notification routing, tool-output admission and more; each decision point can be off / shadow (recorded only) / active, all shadow by default so behavior is identical to before
- The judge chain is drag-sortable in the WebUI: built-in classifier providers (OpenCode, Typesafe, Vercel AI Gateway, OpenRouter, Cloudflare Workers AI free tier) sit alongside custom relay judges as peers; the first usable one is the primary judge, later ones are tried in order when it returns a gray zone or fails, and the original rules take over when none is available; risky-command review can only tighten (at most ask for approval), never approve
- Autopilot promotion: a shadow point that collects enough samples is promoted automatically by a statistical gate (samples ≥30, agreement ≥90%, gray-zone rate <20%) and demoted again if quality degrades — no human labeling; points can also be pinned manually in config.yaml
- New Judge Kernel tab in the WebUI (enable switch, providers and models, judge chain, golden-sample test, decision-point matrix) plus a verdict ledger panel; the `judge:` section of `config.yaml` is the single source of truth
- Privacy-safe by default: the ledger does not store judged content, keys can only be referenced by env-var name, and consecutive failures trip a circuit breaker with a silent fallback

## ⬆️ pi-mono Upgraded to v1.3.0

- The embedded pi-mono is upgraded to pi v1.3.0
- Model and provider updates: Codex GPT-6.1 Sol with a 500K context window; thinking can be turned off for Claude Haiku 5.5 / Opus 5; Xiaomi MiMo gains a thinking switch; kimi-coding is back on Chat Completions
- Upstream fixes adopted: errors such as `The upstream provider returned an error` and `The service is temporarily unavailable` are retried; Anthropic strict tool limits fall back on failure; Claude keeps images in error tool results; non-Claude models no longer drop thinking; malformed tool arguments now error instead of keeping a prefix
- MCP: tool `structuredContent` accepts arbitrary JSON values, and cancelled requests are no longer retried after an auth refresh

## 🔧 Fixes

- **Fixed: the first message of a new session appeared twice in history.** The tool-declaration system message injected before the first turn shifted the persist window by one, so the same user message was written twice
- **Fixed: a config hot reload could be overwritten by the previous one.** Overlapping reloads (file watcher, WebUI save, env) are now applied serially in arrival order
- **Fixed: WeChat messages could be processed twice or dropped.** A batch is processed before its cursor is committed, failed batches retry with exponential backoff without re-running completed turns, and reply tokens are written sequentially
- **Fixed: Feishu messages were silently dropped when the queue was full.** Queue rejections are now reported, and one failing task no longer blocks later messages in the same session
- **Fixed: the session agent / model / reasoning-level maps grew without bound.** All three are now bounded (500 entries, least-recently-used evicted)
- **Fixed: the OpenCode free judge tier used a request URL that did not match the official docs.** `jev-1.13` and `jev-1.13-free` are pinned to the documented System One endpoint so a model-catalog resync cannot override them
