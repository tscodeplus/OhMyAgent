v4.3.0：带来 Jev 判断内核（Judgment Kernel）——以判断模型（Jev / System One 协议）驱动 15 个决策点，全部默认 shadow 起步，支持自定义 relay 裁判，并附全提供商 contract 测试矩阵。

## 🧩 新增：判断内核（主要更新）

- 内核位于第一方目录 `src/judge/`：判断引擎 + 决策点目录 + 判决账本 + 熔断；配置以 `config.yaml` 的 `judge:` 节为唯一事实源（显式主裁判、显式级叠链，无 env 探测链）；无该节或 `judge.enabled: false` 时整层不生效，行为与引入前逐位一致
- 15 个决策点全部接入模式矩阵与账本：
  -.tool token economy：`tool.admission`（工具长输出分块准入）、`testlog.fold`（测试日志重复块折叠，纯规则 + judged 两档）、`intent.classify`（消息意图/思考档位）、`skills.disclosure`（技能触发弱命中再判）
  - 记忆与上下文存量：`memory.capture` / `memory.worth` / `memory.merge` / `context.forget` / `context.compact`
  - 安全与调度：`turn.drift` / `turn.completion` / `tool.risk`（只可能收紧为问人，绝不放行）/ `injection.screen` / `channel.triage` / `notify.routing`
- 判断严格限于有界判断面（choice / noul / score），答案 fail-closed 校验：缺字段、超纲选项一律整包拒绝走兜底，绝不「静默归一化成看起来合理的答案」；灰区级叠（noul ∈ (0.25, 0.75)、choice/score confidence < 0.5）交下一级裁判
- 决策点三态模式 `active / shadow / off`，默认 shadow：判决只记账不改行为；审计后逐点 active，回滚 = 单点改回 shadow/off（热重载即时生效）
- 自定义 relay 裁判（`judge.judges`）：`type: typesafe`（`<baseUrl>/systemone` envelope）与 `type: http`（纯 System One wire，原样 POST `{state, questions}`）；条目含 `baseUrl`、`apiKeyEnv`（密钥只允许以环境变量名引用，禁止内联）与可选 `model`（默认 `jev-latest`）；所有 relay 裁判自动位于内建裁判链之上（含 `routes` 单点覆盖之上），judgeId = 条目名；本地 llama.cpp classifier API 已就绪，但暂无解析路径（`llama-cpp/*` 引用当前按 fail-closed 兜底）
- 内建提供商矩阵开箱可用：OpenCode Zen（含免费 `jev-1.13-free`，需显式选择并每日一次告知数据去向）、TypeSafe、Vercel AI Gateway、OpenRouter（隐藏 slug `~typesafe/jev-latest` 经 compat `registerModel` 注册可达）、Cloudflare Workers AI
- 隐私默认安全：账本默认不保存被审 state（`recordState: false`）；state 在构建时脱敏/截断；免费档永不静默兜底
- 连续失败进入熔断（静默兜底降温，不刷屏）；裁判回答超时/无 key 均记入账本回退原因

## 🧪 测试

- 提供商矩阵 contract 测试（`tests/judge/contract-*.test.ts`）：opencode、typesafe、vercel-ai-gateway、cloudflare-workers-ai（含 `CLOUDFLARE_ACCOUNT_ID` 环境处理）、openrouter 隐藏 slug、本地 llama.cpp 行为基线、自定义 relay（本地 mock HTTP，确定性）；网络用例在对应 key 缺失时自动跳过

## 🖥️ WebUI

- 「模型」tab 新增「判断内核」sub-tab：启停、provider 与模型选择（附 key 配置状态与免费档数据去向提示）、级叠链编辑器、金样例测试按钮（choice/noul/score 各一发真实请求）、决策点模式矩阵
- 仪表盘新增判决账本查看组件：最近判决、命中统计与熔断状态

## 🚀 上线指引

1. 体验期零行为改变：`judge.enabled: true` + `modes: { default: shadow }`，跑若干真实会话后审查账本
2. 逐点 active：每点 ≥30 样本、误判率 <10% 后一次只开一个点（先开纯增益点）
3. 回滚与关闭：单点改回 `shadow`/`off` 热重载即时生效；`judge.enabled: false` 即完整关闭，所有挂接点行为与引入前一致

v4.3.0 introduces the Jev judgment kernel — 15 decision points driven by judgment models (Jev over the System One protocol), all shadow-first, with custom relay judge support and a full provider-matrix contract test suite.

## 🧩 New: Judgment Kernel (Main Update)

- The kernel lives in the first-party `src/judge/` directory: judgment engine + decision-point registry + verdict ledger + circuit breaker. The `judge:` section of `config.yaml` is the single source of truth (explicit primary judge, explicit cascade — no env-probe chain); the whole layer is inert when the section is absent or `judge.enabled` is false, byte-identical to pre-kernel behavior
- All 15 decision points are wired into the mode matrix and ledger:
  - Tool token economy: `tool.admission` (chunked admission for long tool results), `testlog.fold` (exact-repetition test-log folding, rule-based plus a judged pass), `intent.classify` (message intent / thinking tier), `skills.disclosure` (re-judging weak skill-trigger hits)
  - Memory and context stock: `memory.capture` / `memory.worth` / `memory.merge` / `context.forget` / `context.compact`
  - Safety and dispatch: `turn.drift` / `turn.completion` / `tool.risk` (tighten-only: may force an approval card, never auto-approves) / `injection.screen` / `channel.triage` / `notify.routing`
- Judgment stays on the bounded surface (choice / noul / score) with fail-closed answer validation: missing fields or out-of-criteria answers reject the whole result and fall back — never silently normalized into plausible answers. Gray zones (noul ∈ (0.25, 0.75), choice/score confidence < 0.5) cascade to the next tier
- Three modes per point — `active / shadow / off`, default shadow: judged calls are only recorded, behavior is unchanged; promote per point after audit, roll back by switching the point back to shadow/off (hot reload applies instantly)
- Custom relay judges (`judge.judges`): `type: typesafe` (envelope at `<baseUrl>/systemone`) and `type: http` (plain System One wire, POST `{state, questions}` verbatim). Entries carry `baseUrl`, `apiKeyEnv` (env-var NAME only — inline keys are rejected) and an optional `model` (default `jev-latest`); every relay judge sits automatically above the built-in chain, including above `routes` overrides, with judgeId = entry name. The local llama.cpp classifier API is in place but has no resolution path yet (`llama-cpp/*` refs currently fall back fail-closed)
- The built-in provider matrix works out of the box: OpenCode Zen (including the explicit free `jev-1.13-free` tier with its once-per-day data-notice), TypeSafe, Vercel AI Gateway, OpenRouter (hidden slug `~typesafe/jev-latest` resolves via compat `registerModel`) and Cloudflare Workers AI
- Privacy-safe defaults: the ledger does not persist judged state by default (`recordState: false`); state is truncated/scrubbed at build time; the free tier never silently falls back
- Consecutive failures trip the circuit breaker (silent degraded fallback, no log spam); timeouts and no-key drops are ledgered with their fallback reason

## 🧪 Tests

- Provider-matrix contract tests (`tests/judge/contract-*.test.ts`): opencode, typesafe, vercel-ai-gateway, cloudflare-workers-ai (including `CLOUDFLARE_ACCOUNT_ID` handling), the OpenRouter hidden slug, the local llama.cpp behavior baseline, and custom relay judges (deterministic local mock HTTP); network cases auto-skip when the matching key is absent

## 🖥️ WebUI

- New "Judge" sub-tab in the Models tab: enable switch, provider & model pickers (with key status and free-tier data notice), cascade chain editor, a golden-sample test button (one real call each for choice/noul/score) and the decision-point mode matrix
- New judgment ledger component on the dashboard: recent verdicts, hit stats and breaker states

## 🚀 Rollout Guidance

1. Zero-behavior-change experience: `judge.enabled: true` plus `modes: { default: shadow }`; run real sessions, then audit the ledger
2. Promote point by point: ≥30 samples and a <10% error rate per point before switching to active, one point at a time (pure-gain points first)
3. Rollback & off: a single point back to `shadow`/`off` applies via hot reload; `judge.enabled: false` fully disables the kernel and every hook point behaves exactly as before
