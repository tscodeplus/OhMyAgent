v4.2.0-beta2 是 4.2 系列第二个测试版，主要修复 MCP 配置保存与桌面端更新检查的问题。

## 🔧 MCP 修复

- **修复：参数列表里的灰色 `-y` 占位符看似已填、保存后却丢失。** 空行现按占位默认值保存——命令解析为 `npx` 时写入真实 `-y`（含命令留空的兜底），其他运行时（uvx、python -m 等）忽略，避免误改正常预设；占位提示与实际保存值同源，不会再漂移
- **新增：保存时校验服务器工作目录是否存在。** 此前目录缺失要等到连接时才报误导性的 `spawn cmd.exe ENOENT`；现在保存与「测试连接」都直接给出真实原因
- cwd 占位示例改为 `./data` 并说明路径解析规则（`~` 不会展开，相对路径锚定 agent home）

## 🔧 桌面端

- **修复：更新检查在 TUN 代理 / 慢 DNS 环境下总是超时。** 抓取超时 10s → 30s（原预算要覆盖整条重定向链，每跳在慢 DNS 下就要 5-6s）；网络诊断探针 URL 改为按当前版本推导，不再硬编码旧版本资源

v4.2.0-beta2 is the second beta of the 4.2 line, fixing MCP config saving and the desktop update check.

## 🔧 MCP Fixes

- **Fixed: the gray `-y` placeholder in the args list looked filled in but was dropped on save.** A blank row now saves as the placeholder default — a real `-y` when the command resolves to `npx` (including the blank-command fallback), and ignored for other runtimes (uvx, python -m, …) so working presets are not corrupted; the placeholder and the saved value come from the same expression and can no longer drift
- **New: the server cwd is validated to exist at save time.** A missing directory used to surface only at connect time as a misleading `spawn cmd.exe ENOENT`; saving and Test Connection now report the real cause
- The cwd placeholder is now `./data` with a hint explaining path resolution (`~` is not expanded; relative paths anchor to the agent home)

## 🔧 Desktop

- **Fixed: update checks always timed out behind a TUN-mode proxy or slow DNS.** Fetch timeouts raised 10s → 30s (the old budget had to cover the whole redirect chain, where each hop costs 5-6s on slow DNS); the network diagnostic probe URL now derives from the current version instead of a hardcoded old release asset
