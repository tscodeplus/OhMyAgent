v2.4.0-beta4 加固 macOS Computer Use 的 Swift AX 工具层：编译缓存改为内容寻址，杜绝 /tmp 被清空或源码变动时静默重编译导致的 AX 回归；回车键提交改为优先走 AXConfirm，修复 Safari 智能搜索等后台场景下 Enter 失效。

## 🖥️ Computer Use（macOS AX 工具层）

- 编译缓存改为 hash-keyed：AX 工具二进制按源码哈希命名，存放于应用支持目录，一次编译永久复用；原子替换 + 显式 COMPILE_FAILED 错误，不再静默返回 null
- 修复 /tmp 缓存的两处隐患：world-writable 且重启即清空；mtime 比较会让任何一次内嵌源码变动静默重编译，覆盖已打补丁的二进制，导致 AX 层回归（macOS 15 排查中曾两次触发）
- press_key Enter 优先提交聚焦元素的 AXConfirm（新增 confirmfocused 子命令），CGEvent 后台投递兜底——Safari（及多数 Cocoa 应用）会忽略后台 CGEvent 的 Enter 提交智能搜索，值已写入却无导航动作

***

v2.4.0-beta4 hardens the macOS Computer Use Swift AX layer: the compiled tool cache is now content-addressed so /tmp clears or source changes can never silently recompile over a patched binary, and Enter now commits through the focused element's AXConfirm before falling back to CGEvent posting.

## 🖥️ Computer Use (macOS AX tool layer)

- Hash-keyed compile cache: the AX tool binary is named by source hash in the app-support dir — compile once per source, atomic move, explicit COMPILE_FAILED error instead of a silent null
- Removed both /tmp cache hazards: world-writable and wiped on reboot; and the mtime dance let any invocation with different embedded source silently recompile, overwriting a patched binary and regressing the AX layer (hit twice during the macOS 15 hunt)
- press_key Enter prefers the focused element's AXConfirm (new confirmfocused subcommand) over background CGEvent posting — Safari (and most Cocoa apps) ignore background Enter for smart-search commits: the value was set but navigation never started
