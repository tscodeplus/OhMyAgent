v3.0.0 是一次可靠性与体验的大版本升级：关闭审批/鉴权绕过链路（默认保护所有 WebUI 路由、敏感端点强制鉴权、审批失败即拒绝），Agent 流式链路新增瞬时错误重试与工具循环守卫，全部渠道接入友好分类错误提示，WebUI 流式可靠性整体翻修，并带来移动端 UX 重构与服务一键重启。性能上完成系统提示词字节稳定化、会话缓存 LRU 化与启动并行化，内嵌 pi-mono 升级至 v0.84.3。

## 🔒 安全

- 关闭审批/鉴权绕过链：webuiAuthHook 先于扩展路由注册，默认保护全部路径（公共路径走白名单）；此前 Fastify 钩子对后注册路由不生效，扩展端点处于裸奔状态
- `/api/subscriptions` 与 `/wechat/login/start` 强制鉴权；微信扫码轮询改为服务端激活 bot，不再向调用方返回 botToken
- 审批失败即拒绝（fail closed）：非飞书渠道的文件访问审批、非应用类 computer_use 动作不再默认放行；未知工具默认按可变更/需审批处理；`timeout_action=allow` 不再自动放行高风险请求
- Telegram webhook secret 改用恒时比较，未配置时告警
- 进程级 `unhandledRejection` / `uncaughtException` 兜底，退出前回滚已启动服务

## 🤖 Agent 可靠性与任务完成率

- 瞬时错误自动重试：新增 retrying-stream 包装层，对传输/供应商瞬时失败（含流中断）做有界重试，`agent.max_retries` 可配（默认 2）；实现在 OhMyAgent 侧，内嵌 pi-mono 保持零改动
- 工具循环守卫：同一工具连续失败 ≥3 次注入诊断提示，`max_tool_cycles`（默认 25）硬停死循环；大体积工具结果压缩为摘要 + 归档引用（file_read 可取全文）
- 分层系统提示词：任务执行指引（plan-verify-execute）、XML 技能/工具目录层（字节稳定、缓存友好）；注入上下文（记忆/人设/canvas）统一包进 XML 块
- 空白 system_prompt 改为基础层兜底，不再回落 legacy 占位符
- 会话标题生成：按显示宽度（CJK=2）预算截断，不再把混合文字标题腰斩；主模型失败时自动沿 `fallback_models` 降级生成
- 错误元数据持久化：失败流不再显示误导性的 ↓0 ↑0 token 统计；回合看门狗改为按无活动计时，长任务不再被墙钟误杀

## 💬 友好错误提示（全渠道）

- 供应商/流错误自动分类（限流、模型不存在、鉴权、网络、未知），聊天气泡与 Feishu/Telegram/WeChat/QQ 全部渠道渲染友好、可操作的提示（指明失败模型，原始错误折叠在"详情"里）
- 重试/降级成功后自动吞掉瞬时错误，不惊扰用户；网关型 `401: Model X is not supported` 正确归类为模型配置错误而非 API key 问题
- 重试与降级全过程写入日志（provider/model/attempt），可观测可排查
- `UI_LANGUAGE` 环境变量仅作默认值，config.yaml 显式配置优先

## 🚀 性能

- 系统提示词字节稳定化：当前时间逐轮注入最后一条用户消息而非写死在系统提示中，供应商前缀缓存命中率大幅提升；cron 样板文案精简约 40%
- 会话级缓存从每回合闭包提升为模块级有界 LRU（快照/人设/桥接/压缩），并按 `agentId:session` 命名空间隔离，中途切换 Agent 不再串状态
- token 估算按消息对象记忆化、记忆检索短 TTL 缓存、prompt assemble 结果记忆化；工具目录按生效 profile 过滤，模型只看得见可执行工具
- 启动并行化：记忆服务、技能注册表、computer-use、订阅凭据注入等独立 I/O 并发执行
- Shell 工具改用 spawn + 有界 head/tail 流式捕获（峰值 ~2MB），`/stop` 以进程组级联杀干净子孙进程；新增 `agent.request_timeout_ms`（默认 120s）快速失败无响应的供应商
- SQLite 开启 `synchronous=NORMAL` + 页缓存 pragma（WAL 安全，减少 fsync）

v3.0.0 is a major reliability and experience release: the approval/auth bypass chain is closed (all WebUI routes protected by default, sensitive endpoints require auth, approvals fail closed), the agent streaming pipeline gains transient-error retry and a tool-cycle guard, friendly categorized provider errors land on every channel, WebUI streaming gets a full reliability overhaul, and mobile UX is rebuilt around a fixed top bar with bottom sheets. Performance work includes byte-stable system prompts, LRU session caches, and parallelized startup; the embedded pi-mono is upgraded to v0.84.3.

## 🔒 Security

- Closed the approval/auth bypass chain: webuiAuthHook now registers before extension routes and protects all paths by default (public allowlist); Fastify hooks previously did not apply to routes registered later, leaving extension endpoints unprotected
- `/api/subscriptions` and `/wechat/login/start` now require auth; WeChat QR poll activates the bot server-side instead of returning botToken to callers
- Fail closed on approvals: file-access approval for non-Feishu channels and non-app computer_use actions no longer silently pass; unknown tools default to mutating/approval-required; `timeout_action=allow` never auto-approves high-risk requests
- Telegram webhook secret uses a constant-time compare, with a warning when unconfigured
- Process-level `unhandledRejection` / `uncaughtException` handlers roll back started services before exit

## 🤖 Agent Reliability & Task Completion

- Transient-error retry: new retrying-stream wrapper with bounded retries on transport/provider failures (including mid-stream disconnects), configurable via `agent.max_retries` (default 2); implemented OhMyAgent-side so embedded pi-mono stays untouched
- Tool-cycle guard: a same-tool failure streak ≥3 injects diagnostics and `max_tool_cycles` (default 25) hard-halts runaway loops; oversized tool results are compacted to summary + archive reference (file_read for full output)
- Layered system prompts: task-execution guidance (plan-verify-execute) plus XML skills/tools catalog layers (byte-stable, cache-friendly); injected context (memory/persona/canvas) wrapped in XML blocks
- Blank system_prompt falls back to base layers only, no legacy placeholder
- Session titles budgeted by display width (CJK=2) so mixed-script titles are no longer chopped mid-word; generation falls back through `fallback_models` when the primary model fails
- Error metadata persisted — failed streams no longer show a misleading ↓0 ↑0 token footer; the turn watchdog is inactivity-based so long working turns are not killed by wall clock

## 💬 Friendly Provider Errors (All Channels)

- Provider/stream errors are classified (rate_limited, model_not_found, auth, network, unknown) and rendered as friendly, actionable messages in chat bubbles and on Feishu/Telegram/WeChat/QQ alike — the failed model is named and the raw error hides behind a collapsible "details" section
- Transient errors are suppressed when retry/fallback recovers; gateway bodies like `401: Model X is not supported` classify as model-config errors instead of API-key problems
- Retries and fallbacks are fully logged (provider/model/attempt) for observability
- `UI_LANGUAGE` env is now default-only; explicit `ui_language` in config.yaml wins

## 🚀 Performance

- Byte-stable system prompts: current time is injected per-turn into the last user message instead of the system prompt, greatly improving provider prefix-cache hit rates; cron boilerplate trimmed ~40%
- Session-level caches hoisted from per-turn closures to module-level bounded LRUs (snapshot/persona/bridge/compression) and namespaced by `agentId:session`, so mid-chat agent switches no longer share state
- Token estimates memoized per message, short-TTL cache for grouped memory retrieval, memoized prompt assembly; the tools catalog is filtered by the effective profile so the model only sees executable tools
- Parallelized startup: memory services, skill registry, computer-use and subscription credential injection run concurrently
- Shell tool rewritten as spawn with bounded head/tail stream capture (~2MB peak); `/stop` kills the detached process group; new `agent.request_timeout_ms` (default 120s) fails fast on unresponsive providers
- SQLite now runs `synchronous=NORMAL` + page-cache pragmas (WAL-safe, fewer fsyncs)

## 🖥️ WebUI

- Streaming reliability overhaul: snapshot-aware message pruning (in-flight content no longer disappears), SSE keepalive every 15s (no more drops during long tool runs), end-to-end clientMsgId dedup, streaming-state reset on session switch, and a restored thinking indicator when returning to a running session
- Auto-scroll fixes: scroll intent captured at the event level, rAF-coalesced instant snaps, and a translucent "back to bottom" pill while reading history
- Consecutive tool calls fold into a single group; MessageBubble uses React.memo so deltas no longer re-parse the full markdown

## 📡 Channel Fixes

- **Fixed: the approve/reject/ignore buttons on the task-failure analysis card did nothing on any channel.** They now work everywhere: Feishu (card buttons + HTTP webhook), Telegram (callback buttons), QQ (interactive keyboard), WeChat (numeric replies 1/2/3) — all with proper feedback
- **Fixed: final answers lost and log spam after long Feishu tasks.** When Feishu times out and closes the streaming card, the system now stops the pointless flush retries (previously every 600ms forever, even through shutdown) and delivers the remaining content via the terminal card
- **Fixed: Feishu international region (`region=lark`) config had no effect and token expiry broke all requests.** It now applies to every request; invalid-token fetches retry once
- **Fixed: occasional message loss on WeChat.** The cursor used to advance before processing, so a mid-batch failure skipped those messages forever; it is now saved only after the batch completes, and failures re-fetch
- **Fixed: intermittent QQ disconnects and slow token-expiry recovery.** String-format expires_in from the API is now tolerated; concurrent token refreshes collapse into one; connections are mutex-guarded against double-connect/double-close

## 🧠 Memory & Data Fixes

- **Fixed: memory hygiene could mis-purge or skip expired memories.** Timestamp formats aligned, purges keep the vector and jieba FTS indexes consistent; FTS backfill inserts only missing rows so search ranking stays honest
- **Fixed: project deletion silently failing with leftover approval records.** The cascade delete now completes the approval/episodes/tool_runs FK chain inside a transaction
