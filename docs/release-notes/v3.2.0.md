v3.2.0 的主角是聊天输入框：新增 Agent / 模型选择器，会话内即可切换智能体与模型；重试与降级全程可视化，模型故障切换不再"静默卡住"。

## ✨ 体验升级

### 聊天输入新增 Agent / 模型选择器

- 输入框新增两个下拉选择器：**Agent 选择器**（默认会话项目默认智能体）与**模型选择器**（默认该 Agent 主模型，列出所有已配置供应商的模型），选择即时生效——Agent 绑定到当前会话，模型覆盖本次对话
- 模型下拉支持**关键词搜索**（匹配供应商 / 模型 ID / 显示名称），供应商与模型按 A-Z 排序
- 两个菜单右上角均有 **+ 按钮直达对应设置页**（智能体管理 / 模型供应商），配好即回来用

### 界面打磨

- 表单控件统一交互质感：原生 `<select>` 替换为应用内自定义下拉（支持键盘导航与分组），聚焦框改为 focus-visible（鼠标点击不再出现亮圈）
- 流式输出中输入内容时显示发送按钮（可直接插话 steer）
- 设置「模型与路由」默认打开供应商子页；修复 Safari/iOS 缓存旧版页面 HTML 的问题（重建后强制拉取最新 index.html，哈希资源标记为不可变）

## 🛡️ 重试 / 降级可视化与可靠性

- 模型重试与降级全程可见：重试回调与降级切换发出 `stream_retry` 事件，WebUI 聊天输入框显示琥珀色状态行（如「主模型失败，正在尝试备用模型…」），恢复后自动消失；看门狗将重试视为活动，降级链不再中途被误判卡死
- **降级模型粘性固定**：一次运行中备用模型成功应答后，后续工具轮次直接沿用，不再每轮重走整条失败链
- 修复降级切换时 `message_end` / 重试状态重复下发的问题；请求超时默认 120s 收紧至 60s，整条降级链的最坏静默耗时减半
- 任务中断错误卡样式降噪：去掉大红底色，改为弱化的标题与中性灰详情

## 🔧 修复

- 全新安装下 Default Agent 产生孤立的 `/` 模型引用导致选择器空白

v3.2.0's headline is the chat input: new Agent / Model selectors let you switch agents and models right inside a conversation, and retry/fallback progress is now fully visible instead of silently hanging.

## ✨ Experience Upgrade

### Agent / Model Selectors in Chat Input

- Two new dropdowns next to the slash button: an **agent selector** (defaults to the session project's default agent) and a **model selector** (defaults to the agent's primary model, listing models from all configured providers) — the agent binds to the session and the model overrides the conversation, effective immediately
- The model dropdown has **keyword search** across provider / model id / display name, with A-Z sorting
- Both menus carry a **+ button deep-linking into settings** (agents tab / providers sub-tab) — configure, then come right back

### UI Polish

- Unified form-control feel: native `<select>` replaced by an in-app custom dropdown with keyboard navigation and groups; focus rings are now focus-visible so mouse clicks leave no bright ring
- The send button shows during streaming when you've typed content (steer inline)
- Settings' Models & Routing opens on the Providers sub-tab by default; Safari/iOS no longer serves stale page HTML after rebuilds (no-cache index.html, immutable hashed assets)

## 🛡️ Visible Retry / Fallback & Reliability

- Retries and fallback switches are now visible: they emit `stream_retry` events and the WebUI chat input shows a transient amber status line (e.g. "primary failed, trying fallback model…") that clears on recovery; the watchdog counts retries as activity so a failing fallback chain no longer trips the 300s watchdog mid-chain
- **Sticky fallback per run**: once a fallback model answers, subsequent tool rounds reuse it instead of re-walking the whole failure chain each round
- Fixed duplicate `message_end` / retry events on fallback switches; the default request timeout tightens from 120s to 60s, halving worst-case silent failover time
- The task-interrupted error card tones down: red background dropped for a muted title and neutral gray details

## 🔧 Fixes

- Fresh installs no longer produce a dangling `/` model ref on the synthesized Default agent, which blanked the selectors
