v4.2.0 正式版：带来 MCP（Model Context Protocol）完整支持，内嵌 pi-mono 升级至 v1.0.4，并集中修复测试版期间发现的问题。

## 🧩 新增：MCP 支持（主要更新）

- 接入外部 MCP 服务器，工具以 `mcp__<服务器>__<工具>` 形式进入工具列表：支持 stdio 与 streamable HTTP 两种传输、断线自动重连、OAuth 登录（含无浏览器环境的粘贴 URL 流程）
- WebUI 新增 MCP 集成标签页：安装/卸载、启用停用、逐工具暴露控制、鉴权、实时日志与资源查看
- 配置以 `config.yaml` 的 `mcp:` 节为唯一来源（可用 `pnpm mcp:import` 一次性导入标准 `mcp.json`）；无该节时整层完全不生效
- 大输出自动落盘到 offload 目录；提供资源读取工具
- 新增 `docs/MCP.md` 使用指南

## ⬆️ 升级 pi-mono 至 v1.0.4

- 自上游首个大版本 v1.0.0 起连续同步至 v1.0.4，本地补丁全部干净合并
- 模型目录更新：Azure 供应商更名（api id 与环境变量不变）、支持 Foundry 部署的 Azure Chat Completions
- 上游修复一并采纳：Bedrock HTTP/2 会话超时被正确识别为可重试；MCP OAuth 动态注册发送 OIDC `application_type`（修复部分 OIDC 服务器拒绝回环回调）；Anthropic 内联工具定义、按思考等级采样参数、ChatGPT OAuth 端口占用报错、Retry-After 兜底

## 🔧 修复

- **修复：MCP 工具在部分意图下从模型可见列表中消失。** 消息命中「网络搜索」等意图规则时所有 `mcp__*` 工具被过滤，`tool_search` 返回不含 MCP 的目录，模型误判服务器未启用（实际已注册全部工具）
- **修复：MCP 参数列表里的灰色 `-y` 占位符看似已填、保存后却丢失。** 空行现按占位默认值保存（命令解析为 `npx` 时写入真实 `-y`，其他运行时忽略），不再误改正常预设

v4.2.0 is the stable release: full MCP (Model Context Protocol) support, the embedded pi-mono upgraded to v1.0.4, and fixes for the issues found during the betas.

## 🧩 New: MCP Support (Main Update)

- External MCP servers now contribute tools as `mcp__<server>__<tool>`: stdio and streamable HTTP transports, automatic reconnect, OAuth login (including a paste-a-URL flow for headless environments)
- New MCP tab in the WebUI: install/uninstall, enable/disable, per-tool exposure control, auth, live logs and resources
- The `mcp:` section of `config.yaml` is the single source of truth (`pnpm mcp:import` converts a standard `mcp.json` once); the whole layer is inert when that section is absent
- Large outputs spill to the offload directory; resource-reading tools are included
- Added `docs/MCP.md`

## ⬆️ pi-mono Upgraded to v1.0.4

- Synced continuously from the first upstream major (v1.0.0) through v1.0.4, with all local patches merged cleanly
- Model catalog updates: the Azure provider is renamed (api id and env vars unchanged) and Foundry-deployed Azure Chat Completions is supported
- Upstream fixes adopted: Bedrock HTTP/2 session timeouts are now recognized as retriable; MCP OAuth dynamic registration sends the OIDC `application_type` (fixing OIDC servers that rejected loopback callbacks); plus Anthropic inline tool definitions, per-thinking-level sampling params, the ChatGPT OAuth port-in-use error and a Retry-After fallback

## 🔧 Fixes

- **Fixed: MCP tools vanished from the model-facing tool list under certain intents.** When a message matched a rule such as "web search", every `mcp__*` tool was filtered out, so `tool_search` served an MCP-less catalog and the model concluded the server was not enabled — while all tools were in fact registered
- **Fixed: the gray `-y` placeholder in an MCP args list looked filled in but was dropped on save.** A blank row now saves as the placeholder default (a real `-y` when the command resolves to `npx`, ignored for other runtimes), so working presets are not corrupted
- **Fixed: a missing MCP server working directory only failed at connect time with a misleading message** (`spawn cmd.exe ENOENT`). Saving and Test Connection now report the real cause
- **Fixed: desktop update checks always timed out behind a TUN-mode proxy or slow DNS.** Fetch timeouts raised 10s → 30s, and the diagnostic probe URL now derives from the current version
