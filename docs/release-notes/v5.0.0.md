v5.0.0：5.0 正式版——聊天里说过的话现在能被收进「笔记」并带回下一轮对话，各渠道会话能在 WebUI 里读完、归档，界面本身也能装成一个 App。

## 📝 笔记

- 「笔记」是侧栏工具区的第一项：一条笔记有标题、正文、标签和来源，谁写的、什么时候写的一目了然
- 两种来路：聊天里 `/note`（或 `/notes`）把这段对话蒸馏成笔记，命令后可以跟一句指令（如 `/note 只留那几条命令`）；WebUI 里拖选对话文字丢到悬浮球也能记——按住 Alt 拖放是「蒸馏这段」，不按是「原样记下」，触屏上选中文字会直接给出入口
- 捕获有边界：一次最多 3 条、正文最多 1200 字、默认脱敏、默认不把工具调用写进去，都可以在设置里调
- 人审才生效：agent 产出的笔记一律是草稿，批准后才进入检索、注入与相关笔记；自己写的直接生效。批准时若标题与已有笔记冲突，会指出撞的是哪一条
- 会自动带到对话里：`notes_search` 随时可查；每轮最多自动注入 2 条已批准笔记的标题与摘要，正文不进 prompt，预算 400 token
- 相关笔记由标签规则推出，不跑模型、不做向量，能回答「为什么相关」
- 只有一种分类轴：标签。作者、渠道、项目作为分面可多选过滤，计数与全文检索共用同一个索引
- 库按页码分页（每页 20 条），批准、置顶、归档之后停在当前页；草稿 14 天后过期；笔记可归档、恢复、显式清除，删除要写原因
- 默认开启（`notes:` 缺省即开启，`enabled: false` 关闭）；开存储不等于开自动批准

## 📥 渠道会话与归档

- 各渠道的会话在 WebUI 侧栏「渠道会话」按渠道与机器人分组，点开就是原样对话记录，只读不打扰
- 项目对话与 IM 会话都能归档，支持批量归档与批量删除；归档只影响列表可见性，记忆、检索与消息投递照常
- 自动归档按「最后活动时间」计时（`archive.auto`，默认关闭、30 天），设置页能预览会移动多少条，也可以立刻跑一次；后台每小时巡检，改开关不用重启
- `/new` 真正开出一段新对话，`/new <标题>` 直接命名，一段会话不再挤在同一个渠道会话行里
- 分组标签上的机器人名称从平台读取并缓存一天（QQ 的机器人名称设置项随之取消），离线重启后仍然显示

## 🔎 原话检索

- agent 现在能读过往会话的原话：`session_search` 支持按会话、时间范围过滤，返回带上下文的片段，`limit` 是硬上限（片段扩张也算在内），不必只依赖摘要

## 🖥️ 界面与设置

- WebUI 可安装：带图标与独立窗口，从主屏图标启动而不是浏览器标签页
- 首屏每个面板一次读取（同一页共享配置），对话列表分页；抽屉每次打开不再整块重挂
- 设置里保存的自定义模型立刻出现在所有模型下拉中；内置 provider 重命名不再打一个字符就失焦；judge 设置可增删改，删除需要确认，中转 Key 与 API key 一样打码
- 新会话的默认标题跟随界面语言（中文界面是「新对话」）

## ⬆️ pi-mono v1.5.0

- 内置 pi-mono 升级为 pi v1.5.0（308 个上游提交）
- 工具参数校验从 TypeBox 换成新的 `pi-schema`：不依赖 `eval` 的 JSON Schema 校验器（draft 2020-12 / 7，编译成闭包），校验失败会指出具体字段路径
- `AgentTool` 的参数泛型放宽为 `object`，我们 61 处 TypeBox 工具定义无需改动，行为不变
- anthropic / bedrock / openai / mistral / google 的 API 适配与流式 JSON 解析同步上游；5 个本地补丁文件、27 处 `OhMyAgent` 标记全部干净合并

v5.0.0: the 5.0 general release — what was said in a chat can now be captured as a note and carried into the next turn, every channel's conversations can be read and archived inside the WebUI, and the interface itself installs as an app.

## 📝 Notes

- Notes is the first item in the sidebar's tool section: a note carries a title, a body, tags and its sources, and who wrote it when is never in doubt
- Two ways in: `/note` (or `/notes`) in a chat distils the conversation into notes and accepts a trailing instruction (`/note keep only those commands`); in the WebUI you can drag selected chat text onto the floating ball — holding Alt while dropping asks for a distillation instead of the words verbatim, and on a touch screen selecting text offers the entry directly
- Capture is bounded: at most 3 notes per run, 1200 characters of body, redacted by default, tool calls left out by default — all adjustable
- Nothing takes effect unreviewed: agent-distilled notes are always drafts, and only approval puts them into search, injection and related notes; a note you write yourself needs no review. Approving onto a title an existing note owns names the collision
- It arrives in the conversation on its own: `notes_search` is always available, and each turn injects the title and summary of at most 2 approved notes — never a body, inside a 400-token budget
- Related notes come from a tag rule, with no model and no embeddings, and the list can say why a note is there
- One dimension only: tags. Author, channel and project are facets you can multi-select, and their counts share the index with full-text search
- The library pages in numbered pages (20 rows each), and approving, pinning or archiving keeps you where you were; drafts expire after 14 days; a note can be archived, restored or explicitly purged, and deleting one asks for a reason
- On by default (an absent `notes:` section means enabled, `enabled: false` turns it off); turning on storage is not turning on auto-approval

## 📥 Channels and Archiving

- Each channel's conversations sit in the WebUI's 渠道会话 section, grouped by channel and bot; opening one shows the transcript as it happened, read-only
- Project chats and IM conversations both archive, with batch archive and batch delete; archiving is a list-visibility flag only — memory, search and message delivery carry on
- Auto-archive counts from the last activity (`archive.auto`, off by default, 30 days); the settings card previews how many conversations it would move and can run it once immediately, and the hourly job reads the switch live
- `/new` opens a genuinely new conversation and `/new <title>` names it, instead of piling every conversation into one row
- The bot name on each group label is read from the platform and cached for a day (the QQ bot-name setting is gone with it), surviving an offline restart

## 🔎 Raw Transcript Search

- The agent can now read past conversations verbatim: `session_search` filters by session and time range and returns fragments with their context, where `limit` is a hard cap that neighbourhood expansion counts inside — no longer summaries only

## 🖥️ Interface and Settings

- The WebUI is installable: icons and a standalone window, launched from the home screen instead of a browser tab
- Each first-screen panel costs one read (one shared config per page) and the conversation list pages; a drawer opening no longer re-mounts the whole tray
- A custom model saved in Settings appears in every model picker immediately; renaming a built-in provider no longer loses focus after one character; judge settings add and remove with a confirmation on delete, and a relay key is masked like the API keys
- A new session's default title follows the UI language

## ⬆️ pi-mono v1.5.0

- The embedded pi-mono is upgraded to pi v1.5.0 (308 upstream commits)
- Tool-argument validation moves from TypeBox to the new `pi-schema`: an `eval`-free JSON Schema validator (draft 2020-12 / 7, compiled to closures) that names the exact field path when validation fails
- `AgentTool`'s parameter generic widens to `object`; our 61 TypeBox tool definitions need no change, and behaviour is unchanged
- anthropic / bedrock / openai / mistral / google API adaptations and streaming-JSON parsing follow upstream; all 5 locally patched files and all 27 `OhMyAgent` markers merged cleanly

## 🔧 Fixes

- A reply no longer disappears when a skill is activated: the answer body is persisted alongside the skill card
- Deleting an IM transcript leaves no empty 新会话 / 0 条消息 row behind, and the 渠道会话 counts stop over-reporting
- Turning thinking off for background calls now actually reaches the provider, which note distillation and memory extraction both rely on
- A cold session rebuilds the same context a warm one keeps, and injecting the summary no longer replays secrets or expired rows
- The desktop window's close button turns red on hover
