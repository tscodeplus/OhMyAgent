v5.0.0-beta2：知识库退役，笔记本登场——「笔记」把「这个话题我们聊过什么」变成一条条可审、可查、能带进下一轮对话的记录，取代原来的知识页与实体图谱。

## 📝 新增：笔记

- 「笔记」是侧栏工具区的第一项，取代知识库原来的三个页面（知识页 / 待审队列 / 图谱）
- 两种来源：聊天里 `/note`（或 `/notes`）把这段对话蒸馏成笔记，命令后面可以跟一句指令（如 `/note 只留那几条命令`）；WebUI 里拖选对话文字丢到悬浮球也能记——按住 Alt 拖放是「蒸馏这段」，不按是「原样记下」，触屏上选中文字会直接给出入口
- 捕获有边界：一次最多 3 条、正文最多 1200 字、默认脱敏、默认不把工具调用写进去，都可以在设置里调
- 人审才生效：agent 产出的笔记一律是草稿，批准后才进入检索、注入与相关笔记；自己写的直接生效。批准时若标题与已有笔记冲突，会指出撞的是哪一条，让你改名或丢弃
- 会自动带到对话里：`notes_search` 随时可查；每轮最多自动注入 2 条已批准笔记的标题与摘要，正文不进 prompt，预算 400 token
- 相关笔记不花调用费：关联由标签规则推出，不跑模型、不做向量，能回答「为什么相关」
- 只有一种分类轴：标签。作者、渠道、项目作为分面可多选过滤，计数与全文检索共用同一个索引
- 生命周期只有两个判定：草稿要么批准进库，要么写个理由删除（内容连同证据、关联与索引一起抹掉，只留一条被拒记录用于批准率统计）；草稿不会因时间流逝而消失。笔记可归档、恢复，也可显式清除
- 默认开启：`notes:` 缺省即开启（与 `mcp:`、`judge:` 不同——页签对所有部署可见，缺省关闭等于打开一个空页面），`enabled: false` 关闭。开存储不等于开自动批准

## 🧹 移除：知识库与实体图谱

- 工具 `knowledge_get` / `knowledge_search` / `knowledge_write` / `entity_query`、命令 `knowledge:*` 与 `graph:*`、相关设置页与 API 全部下线
- 升级后数据库会删掉知识库与图谱的表（`knowledge_*`、`entity_*`、`memory_links`）。**这些内容不会迁移进笔记**——要留存的，请先在 v5.0.0-beta1 用 `pnpm knowledge:export`（知识页）和 `pnpm graph:export`（图谱）导出
- 原话检索 `session_search` 不受影响

## 🔧 修复

- 后台调用关闭 thinking 现在真的生效：这个开关过去只写进了配置，请求里并没有按各网关实际读取的形式发出去。笔记蒸馏与记忆抽取都用它
- 冷会话恢复：会话运行时被回收后，下一条消息重建的上下文与热会话一致，不再少一段
- 不再逐轮重放密钥与过期摘要：注入会话摘要时，密钥和已经失效的摘要行不再进入 prompt

v5.0.0-beta2 retires the knowledge base and ships notes: "what did we say about this?" becomes a set of rows you can review, search and carry into the next turn, replacing the knowledge pages and the entity graph.

## 📝 New: Notes

- Notes is the first item in the sidebar's tool section, replacing the knowledge hub's three pages (pages / review queue / graph)
- Two ways in: `/note` (or `/notes`) in a chat distils the conversation into notes and accepts a trailing instruction (`/note keep only those commands`); in the WebUI you can drag selected chat text onto the floating ball — holding Alt while dropping asks for a distillation instead of the words verbatim, and on a touch screen selecting text offers the entry directly
- Capture is bounded: at most 3 notes per run, 1200 characters of body, redacted by default, tool calls left out by default — all adjustable
- Nothing takes effect unreviewed: agent-distilled notes are always drafts, and only approval puts them into search, injection and related notes; a note you write yourself needs no review. Approving onto a title an existing note owns names the collision, so you retitle or discard instead of guessing
- It arrives in the conversation on its own: `notes_search` is always available, and each turn injects the title and summary of at most 2 approved notes — never a body, inside a 400-token budget
- Related notes cost nothing: relations come from a tag rule, with no model and no embeddings, and the list can say why a note is there
- One dimension only: tags. Author, channel and project are facets you can multi-select, and their counts share the index with full-text search
- Two verdicts, no timers: a draft is either approved into the library or deleted with a reason (body, evidence, relations and index row go; one rejection record stays so the approval rate still counts). Drafts never age out. A note can be archived, restored or explicitly purged
- On by default: an absent `notes:` section means enabled (unlike `mcp:` and `judge:` — the tab is visible in every deployment, so "off until configured" opened a dead page), `enabled: false` turns it off. Turning on storage is not turning on auto-approval

## 🧹 Removed: Knowledge Base and Entity Graph

- The `knowledge_get` / `knowledge_search` / `knowledge_write` / `entity_query` tools, the `knowledge:*` and `graph:*` commands, their settings page and their API are gone
- The upgrade drops the knowledge and graph tables (`knowledge_*`, `entity_*`, `memory_links`). **Nothing is migrated into notes** — to keep any of it, export it on v5.0.0-beta1 first with `pnpm knowledge:export` (pages) and `pnpm graph:export` (graph)
- `session_search` is unaffected

## 🔧 Fixes

- Turning thinking off for background calls now actually takes effect: the switch only reached config before, never the request in the shape each gateway reads. Note distillation and memory extraction both rely on it
- Cold session resume: after its runtime is reclaimed, a session rebuilds the same context a warm one keeps, no segment short
- Secrets and expired summaries are no longer replayed every turn: neither reaches the prompt along with the injected summary
